# Contributing

Use synthetic examples and keep the framework independent of player, cast, setting, rules edition and assistant provider. A new configuration feature must serve more than one invented campaign.

For bug reports include the command, package/Python/Node version, a minimal synthetic fixture, expected behavior and actual output. Remove credentials, game IDs, private transcripts, character details and paid source prose. Do not upload live Roll20 receipts.

Use focused tests for the changed behavior and inspect representative output. Run the bridge harness when bridge code changes. Documentation changes need command/link review; they do not justify a large unrelated test run. Never claim test counts establish good storytelling.

Keep one authoritative record per fact. Prefer a better owner selector or dependency over another duplicated summary. Preserve full character profiles and accepted emotional history. A smaller context is useful only if it retains the evidence needed for decisions.

Keep privileged operations bounded. Do not add live game writes or external messaging as a side effect of retrieval. Explain new permissions and failure behavior. Do not place secrets or environment-specific paths in code.

Contributions are made under the repository's MIT license. Third-party adventure/source material needs its own permission and must not be bundled merely because it is accessible in a game.
