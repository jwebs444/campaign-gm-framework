# Transfer to another GM

Transfer only when explicitly requested. Normal context recovery is not a new chat or a repeated intake examination.

Resolve only authorized ordinary work to the requested boundary. Stop for unresolved player choices and meaningful events. Reconcile state, resources, effects, knowledge, operations, development, accepted history and corrections. Preserve HOLD if the player requested a pause.

Verify affected recovery and preparation outputs. Record the exact current location/time, last delivered exchange, pending player input, relevant cast, active effects/resources and next boundaries. Link full profiles and applicable sources rather than substituting a compressed cast list.

Create an as-of transfer note under the excluded `handoffs/` directory. It is evidence of the transfer, not a competing current owner. Point the receiving GM at live owners and `recover --mode fresh`. Do not include rejected branches, hypothetical answer keys or obsolete response examples.

Give the receiving GM the exact authorized player input and applicable instructions. Do not choose an itinerary, resolve pending decisions, refresh resources or award levels merely to simplify the handoff. The new GM must inspect actual scene/source readiness before resuming.

Use the host application's supported chat/task controls only with user authorization. This framework supplies no model API credentials, automatic cross-chat messaging, scheduled world simulation or model-specific dependence.
